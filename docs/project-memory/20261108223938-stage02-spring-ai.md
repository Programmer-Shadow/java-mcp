# 阶段2：Spring AI 自动调用 MCP

> 本文记录最初的独立子项目设计，现已迁移到根目录统一项目。当前结构以 [共用 Maven 项目记忆](20261108230049-shared-stages-layout.md)为准；源码在 src/main/java/lesson/stage02，共用根 pom.xml 和 target。

## 目标、范围、已确认要求
- 用户要求进入阶段2，新建带序号目录，不修改 src/main/java/demo。
- 实现自然语言 → 模型按工具 Schema 生成调用 → MCP 服务执行 → 模型回答。
- 独立 Maven 项目 stage02-spring-ai，保留第一阶段 pom 和源文件；复用第一阶段已打包服务端。
- 不增加 Web 页面、数据库、远程 MCP 或动态工具变更。用户后续确认“就用chatGPT”，实际接入 OpenAI API。沿用当前官方 Chat Completions 工具调用示例的 gpt-5.6-terra，支持环境变量覆盖，设置 reasoning-effort=none、temperature=1。

## 架构与数据
- Spring Boot 3.5.15、Spring AI 1.1.8、Java 17+（本机 JDK21）。选择稳定1.x教学路径，固定版本，不追逐 latest。
- MCP Client starter 根据配置启动第一阶段 jar 的 server 模式，初始化、获取工具并提供 ToolCallbackProvider。
- Stage02Application 读取命令行自然语言，交给 ChatClient；TracingToolCallback 记录工具名、模型生成参数及真实 MCP 结果，委托原工具回调执行。
- 两个进程的 SDK 依赖独立，协议协商互通，不将第一阶段类打包进入第二阶段。
- 无持久化；自然语言、工具说明、工具结果会发送到用户配置的模型服务，演示仅使用加法数据。

## 配置、安全与恢复
- AI_BASE_URL、AI_MODEL、AI_API_KEY 通过环境变量注入；同时支持标准 OPENAI_API_KEY，AI_API_KEY 优先。MCP_SERVER_JAR、MCP_JAVA_COMMAND 可覆盖本地服务启动配置。
- 不记录密钥，不读取或打印现有环境中的秘密值，不自动推送 GitHub。
- 模型支持 OpenAI 兼容 tools/function calling；不支持时明确提示，不用正则解析或伪造 AI 行为。
- 缺少密钥或 jar 时应给出清楚提示；模型请求设超时和有限重试，退出关闭 Spring 上下文释放子进程。
- 控制台仅打印教学数据，不开启 HTTP 全量请求日志。无业务存储，不需要备份。
